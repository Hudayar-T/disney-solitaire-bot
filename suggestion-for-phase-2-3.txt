To build the computer vision layer for Disney Solitaire—specifically detecting face-up cards, facedown overlapping cards, and their underlying dependency graph (which card covers which)—you need a multi-stage approach combining OpenCV contour processing, template matching (or OCR), and geometric bounding-box intersection.

---

### Step 1: Detect All Card Positions & Orientations

Because facedown cards on this board are angled/rotated, standard axis-aligned bounding boxes will fail to accurately isolate corners.

1. **Color Segmentation (Blue Backs vs. White Faces):**
* Convert the board crop to HSV color space.
* Filter out the distinct bright blue of the facedown card backs (`cv2.inRange`).
* Isolate white regions (`cv2.threshold` or HSV range) to find face-up cards.


2. **Find Contours & Rotated Rectangles:**
* Run `cv2.findContours()` on both binary masks.
* For facedown cards, filter by minimum area, then call `cv2.minAreaRect(contour)` to extract the 4 rotated corner coordinates $(x, y)$, width, height, and rotation angle $\theta$.



---

### Step 2: Recognize Face-Up Values & Suits

For face-up cards (which are aligned horizontally/vertically):

1. **Extract Rank/Suit Crop:**
* Crop the top-left or main body of each white face-up card bounding box.


2. **Value Identification:**
* **Option A (Template Matching):** Match the cropped rank symbol against a pre-saved dictionary of template images (`A`, `3`, `4`, `6`, `7`, `9`, `K`) using `cv2.matchTemplate(..., cv2.TM_CCOEFF_NORMED)`.
* **Option B (Lightweight OCR):** Run pytesseract or easyocr on the top-left rank crop.



---

### Step 3: Determine Under/Over Dependencies (Directed Acyclic Graph)

To know which card is underneath another, use Z-order rendering rules and bounding-box geometry:

1. **Overlaps / Polygon Intersection:**
* Convert each detected card's bounding box into a Shapely polygon (`from shapely.geometry import Polygon`).
* Compute pairwise intersections: `poly_A.intersects(poly_B)`. If `intersection_area > threshold`, the two cards overlap.


2. **Resolving Layering (Z-Order / Occlusion):**
* **Face-Up vs. Facedown:** Face-up cards are strictly rendered *on top of* facedown cards. If a face-up card overlaps a facedown card, the face-up card is the parent node blocking the facedown child.
* **Facedown vs. Facedown:** Examine edge continuity or contour area. A complete, unclipped rectangle is on top; a card with a truncated/clipped contour is partially obscured underneath.



---

### Minimal Python OpenCV Skeleton

```python
import cv2
import numpy as np
from shapely.geometry import Polygon

def detect_cards(img_path):
    img = cv2.imread(img_path)
    hsv = cv2.cvtColor(img, cv2.COLOR_BGR2HSV)

    # 1. Mask blue card backs (Adjust HSV ranges as needed)
    lower_blue = np.array([95, 120, 120])
    upper_blue = np.array([115, 255, 255])
    blue_mask = cv2.inRange(hsv, lower_blue, upper_blue)

    contours, _ = cv2.findContours(blue_mask, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)
    card_polygons = []

    for cnt in contours:
        if cv2.contourArea(cnt) > 2000: # Filter small noise
            rect = cv2.minAreaRect(cnt)
            box = cv2.boxPoints(rect)
            box = np.int0(box)
            poly = Polygon(box)
            card_polygons.append(poly)

    # 2. Build Dependency Graph
    dependencies = {} # { card_index: [underneath_card_indices] }
    for i, poly1 in enumerate(card_polygons):
        dependencies[i] = []
        for j, poly2 in enumerate(card_polygons):
            if i != j and poly1.intersects(poly2):
                overlap_area = poly1.intersection(poly2).area
                if overlap_area > 100: # Significant overlap threshold
                    dependencies[i].append(j)

    return card_polygons, dependencies

```
